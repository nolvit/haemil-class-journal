# 수업일지 중심 재설계 — 실행 계획 v1

## 기준과 현황
수업일지가 본체이며 아바타는 출석 보상이다. 기존 수업일지·학생·출결·인증 데이터는 유지한다. 방/가구/배치/레벨/아이템 구매 게임은 새 서비스에 포함하지 않는다.
2026-09-09: feature/journal-avatar-reward 브랜치 생성. 분리된 해밀월드 프로토타입, 방 이미지, 전용 테스트·실행 스크립트·구설계 문서를 작업 트리에서 제거했다. 미커밋 수업일지 변경은 유지했다. 운영 DB는 변경하지 않았다.

## 보존 자료
client/public/avatar-rewards 아래 avatars 및 references 47개 파일 보존. 프롬프트 원본은 client/src/avatarRewards/prompts에 보존. 방 경로를 제외한 assetManifest.json을 별도 구성했다. 의상 이미지는 판매 상품이 아니라 주문 입력 예시다.
전체 소스 복구 사본은 이 작업의 work/before-redesign.tar.gz에 있다(node_modules, .git, dist, data, tmp 제외). 사용자 업로드 data는 원래 위치에서 유지했다. 복구 사본은 배포하지 않는다.

## 확정 기능
- 수업일지 우상단 원형 대표 사진. 클릭하면 전신 이미지·사용 가능/누적 포인트·포인트 원장·컬렉션을 표시한다.
- 1분 1P, 학생별 한국 날짜 하루 최대 150P. 하원 미입력 날짜는 0P.
- 제작 완료 횟수 기준 500 → 1000 → 1500 → 2250, 이후 고정. 컬렉션 카드 수로 가격을 계산하지 않는다.
- 현재 잔액이 제작 비용 이상일 때 제작 버튼 제공. 학생당 진행 주문 1건.
- 한글 자유 입력: 상의/하의/신발/헤어/배경, 복수 장신구 추가. 각 항목에 예시 제공.
- 오리지널/워너비/슈퍼스타 3단계. 기존 ORIGINAL 프롬프트는 새 오리지널 의미와 달라 그대로 연결하지 않는다. LIKENESS의 정체성 유지 기준을 새 오리지널에 적용하고 헤어 주문을 반영한다.
- 관리자 주문 알림 → 주문 데이터 기반 프롬프트 복사 → 관리자 후보 2장 업로드 → 학생 1장 선택 → 컬렉션 저장 → 대표 설정. 대표 사진과 전신 이미지는 같은 카드다.
- 학생용 포인트 설명에 하원 필수, 가격 단계, 150P×15일=2250P를 명시한다.

## 구현 순서와 완료 조건
1. [완료] 로컬 자료 분리·방 프로토타입 제거·프롬프트 및 아바타 에셋 보존.
2. [완료] shared/avatarRewardRules.ts에 적립·가격 정책 및 학생 안내문. 일별 세션 합산, 중복 구간 제거, 상한·미하원·가격 경계 테스트.
3. [완료] 실제 출결 스키마에 연결. 일별 정산키(studentId, KST date)로 중복 적립 방지. 출결 수정은 원장에 차액 기록. 기존 포인트는 게임 잔액과 구분하고 자동 이관하지 않는다.
4. [완료] 영속 저장: reward_accounts, reward_ledger, avatar_orders, avatar_candidates, avatar_collection. 계정 잠금과 트랜잭션으로 주문 차감/환불/선택 중복 방지. 주문 제출 시 비용 저장, 취소 시 1회 환불, 선택 확정 시 완료 횟수 증가. 학생 본인 자료만 조회·변경, 업로드와 환불은 관리자만 허용.
5. [완료] 원형 프로필과 반응형 팝업, 원장·안내문·주문·컬렉션 및 관리자 화면 구현. 얼굴 크롭 위치를 조정할 수 있게 하여 잘못된 자동 크롭을 보완.
6. [완료] 원본 프롬프트를 복사·버전 관리하여 새 한글 자유 주문과 3단계에 맞게 수정. 주문마다 생성 프롬프트 스냅샷 저장.
7. [완료] 권한·동시 주문·중복 하원·출결 수정·환불·후보 선택 테스트, 모바일/데스크톱 확인 후 배포.

## 데이터 전환 주의점
기존 프로토타입 localStorage(haemil-world:prototype:v1)는 신규 잔액의 원천으로 사용하지 않는다. 운영 저장소에 방 데이터가 존재하는지 별도 조사 후 실제 삭제 마이그레이션을 작성한다. 현재 로컬 프로토타입 제거를 운영 DB 정리 완료로 간주하지 않는다.

## 2026-09-09 구현 및 검증 기록
- 3~6단계 구현 완료: 실제 attendance_records 일별 정산, 6개 영속 테이블, 트랜잭션 주문/환불/후보 선택, 학생 팝업·주문·안내·컬렉션·얼굴 크롭, 관리자 마스터/후보 업로드와 새 주문 알림.

- Railway MySQL에 방/월드/가구 테이블 없음 확인. 별도 임시 DB에서 실제 동시 정산/주문/환불/선택과 타 학생 접근을 포함한 12개 시나리오 통과. 임시 DB 삭제 확인.
- 단위/권한 회귀 테스트 74개 통과. 실제 Chrome에서 배포 CSS를 사용한 UI 테스트 통과(1200px/390px). 브라우저 테스트는 합성 API 응답을 사용하며 실제 DB 검증과 별도로 수행했다.
- 검증에서 발견한 MySQL 잠금/스냅샷 경합, 모바일 translate 잘림, 후보 접근성 이름 및 초기 얼굴 크롭을 수정했다.
