# 수업일지 추가하기 검증 메모

- 검증 시작 시 수업일지 팝업에는 상단 `최근 입력 수업 참고`의 `복사·붙여넣기` 버튼과 하단 동작 영역이 분리되어 있다.
- 운영 학생의 수업일지를 변경하지 않기 위해 별도 검증용 학생을 관리자 화면에서 만들고, 완료 직후 학생·연결 출석·수업일지를 완전 삭제한다.
- 평일 모드와 주말 입력 포함 모드에서 각각 내용·과제·비고·임시 저장 상태의 순차 이동과 현재 날짜의 빈 입력 상태를 확인한다.

2026년 8월 27일 관리자 화면에서 기존 활성 학생 32명과 등록 과목을 읽기 전용으로 확인했다. 실제 이관 검증은 기존 수업일지·출석을 건드리지 않기 위해 이 화면에서 새 임시 학생을 만들고, 기존 `수학` 과목에만 연결해 실행한다.

검증용 학생에는 `추가이관검증`, 중1, 검증학교, 주 3회·총 12회·월 원비 130,000원을 입력했다. 아직 저장 전이며, 수학 과목 연결 후 생성된 별도 학생에서만 일지 이동을 확인한다.

검증용 학생은 수학 과목만 연결된 활성 학생으로 생성됐으며, 읽기 전용 조회에서 학생 ID `660001`, 수학 과목 ID `5`를 확인했다. 기존 활성 학생 수는 검증 시작 전 32명이었고, 검증이 끝나면 이 임시 학생과 연관된 수업일지를 완전 삭제해 32명 상태로 되돌린다.

2026년 8월 24일 월요일의 검증용 학생 수학 팝업에서 하단 동작 영역은 `취소 · 추가하기 · 임시 저장 · 저장 · 저장 후 닫기` 순서로 확인됐다. 하단의 기존 복사·붙여넣기 버튼은 없고, 최근 입력 수업 참고가 있을 때만 상단 참고 영역에 복사·붙여넣기가 표시되는 구조다.

월요일에는 `삽입검증-월요일-내용`, `삽입검증-월요일-과제`, `삽입검증-월요일-비고`를 입력하고 팝업을 유지하는 `저장`으로 최종 저장했다. 이 기록은 추가하기 실행 시 화요일로 이동해야 하는 원본이다.

화요일 팝업으로 이동한 뒤 월요일 기록이 `최근 입력 수업 참고`에 표시됐고, 해당 참고 영역 안의 상단 `복사·붙여넣기` 버튼이 유지되는 것을 확인했다. 하단에는 복사·붙여넣기 버튼이 없으며 `추가하기`만 표시된다.

화요일에는 `삽입검증-화요일-내용`, `삽입검증-화요일-과제`, `삽입검증-화요일-비고`를 입력하고 최종 저장했다. 따라서 월요일에 추가하기를 실행하면 화요일에는 월요일 기록, 수요일에는 화요일 기록이 남아야 한다.

추가하기 실행 직전 표에서 월요일·화요일에 각각 위 두 검증 내용이 표시되는 것을 확인했다. 두 기록 모두 출석 상태는 미입력이며, 추가하기는 출석 행을 변경하지 않는 조건을 함께 확인한다.

월요일에서 `추가하기`를 실행한 후 읽기 전용 조회 결과, 8월 24일은 내용·과제·비고가 모두 빈 새 입력 자리로 남았고, 월요일 기록은 8월 25일로, 화요일 기록은 8월 26일로 순차 이동했다. 두 이동 기록의 내용·과제·비고 및 최종 저장 상태(`isDraft = 0`)는 모두 보존됐으며 출석 행은 생성·수정되지 않았다.

동일한 월요일 팝업을 새로 열어 현재 날짜의 입력칸이 빈 상태임을 실제 화면에서 확인했다. 375×812 모바일 화면에서도 취소·추가하기·임시 저장·저장·저장 후 닫기 버튼이 모두 표시되고, 추가하기가 하단 복사·붙여넣기를 대체한 것을 확인했다.

2026년 9월 23일에 격리 수동 휴강 `이관 검증 휴강`을 등록하고, 9월 24~26일 추석 법정공휴일과 이어지는 구간을 구성했다. 별도 학생 `이관일정검증`의 수학 9월 22일 최종 수업일지에 내용·과제·비고를 입력한 뒤, 주말 입력 포함을 끈 상태에서 추가하기를 실행했다. 읽기 전용 조회 결과 현재 날짜 9월 22일은 빈 새 입력 자리로 남았고, 원본은 수동 휴강일 9월 23일·법정공휴일 9월 24~25일·주말 9월 26~27일을 모두 건너뛴 9월 28일로 이동했다. 내용·과제·비고와 최종 저장 상태는 보존됐다. 검증 뒤 학생 ID `690001`의 학생·수강·수업일지·출석·이력과 휴강 ID `60001`을 정확한 식별값으로 모두 삭제했다.
